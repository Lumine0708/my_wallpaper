# Android 平板动态壁纸

更新时间：2026-10-27

这是一个面向 Android 平板、重点适配 Xiaomi/HyperOS 的主屏幕动态壁纸应用。应用会根据设备当前方向读取相互独立的竖屏和横屏配置，支持多张本地图片、顺序或随机播放以及可配置的切换间隔。

应用只管理主屏幕动态壁纸，不写入或替换锁屏壁纸。是否能“仅应用到主屏幕”最终取决于系统或 OEM 的动态壁纸选择器。


## 当前状态

壁纸配置模型 v1 已完成实现、审查和验收，当前版本已经具备：

- 横屏、竖屏两份独立 profile；
- 通过 Storage Access Framework 多选本地图片并持久保留读取权限；
- 图片添加、移除、上移、下移；
- 5、10、30、60 秒切换间隔；
- 顺序循环和洗牌袋随机播放；
- 固定 680 ms 平滑切换；
- 配置原子保存、revision 冲突保护和损坏/未来版本隔离；
- 有界异步解码、失败退避和 active/preview/settings 分来源诊断；
- Xiaomi/HyperOS 动态壁纸列表兼容路径。

在用户首次保存 v1 配置前，应用仍会把 APK 内置图片作为只读 legacy fallback：横屏使用《地出》，竖屏在《蓝色弹珠》和《地出》两张图片间按 10 秒轮换。内置素材均标为公有领域，见[图片来源](bundled-images.md)。首次保存后，用户配置成为唯一数据源；合法空配置、损坏配置或未来 schema 都不会重新启用内置图片。


## 使用方式

1. 启动“平板动态壁纸”。
2. 分别进入“竖屏”和“横屏”，添加图片并设置顺序与间隔。
3. 使用“保存”提交当前方向；另一个方向的配置和未保存草稿不会被覆盖。
4. 点击“选择动态壁纸（请仅应用到主屏幕）”。
5. 系统提供选项时选择“仅主屏幕”，然后用系统设置或 `dumpsys wallpaper` 确认锁屏仍由原组件管理。

Xiaomi 设备使用系统动态壁纸列表进入预览，因为已验证的 HyperOS 3 直接组件选择 Intent 会接受请求后立即退出。该兼容逻辑只按 manufacturer 生效，不使用私有 API 绕过 ROM 限制。

## 产品与安全边界

- 不新增 `android.permission.SET_WALLPAPER`、`WallpaperManager.FLAG_LOCK` 或锁屏写入入口。
- 用户图片只持久化 `content://` URI；日志和诊断不输出完整 URI。
- 横屏和竖屏是仅有的两份 profile，不按图片比例或设备类型增加第三套配置。
- 平滑转场是 renderer 的固定行为，不属于 v1 可编辑 schema。
- 损坏配置只能由用户确认重置；未来 schema 始终只读。
- 预览 Engine 与主屏幕 Engine、横屏与竖屏播放状态相互隔离。

## 已知验证边界

- API 26–27 尚未进行实际模拟器/设备回归；已使用的模拟器和真机验证基线为 API 35。
- instrumentation 尚不能注入一个完全可控的 framework Wallpaper `SurfaceHolder`，真实 surface 提交失败仍需要设备层关注。
- HyperOS 长时间运行、OneKeyClean/低内存清理后的自动恢复仍值得持续观察。
- 播放位置不会作为用户配置写入；是否跨进程重启持久化仍是后续可靠性议题。
